GIS Data Organization in R

A Guide to Structuring RStudio Projects

Before you begin analysis in R, you must establish a system for organizing your files and directories.

You will often deal with large datasets (from colleagues or off the web) alongside specific field data (like fish transect counts or benthic quadrat surveys). Without a deliberate storage strategy, your workflow will quickly become overwhelming and confusing.

This guide covers how RStudio Projects work, how conventions will help you maintain project organization.

1. What RStudio Sets Up Automatically

When you create a new project in RStudio (File > New Project…), RStudio creates a self-contained directory anchored by an .Rproj file. Think of this folder as the physical container for your entire workspace.

Inside that directory, RStudio establishes a clean baseline layout:

Brewers_Bay_Ecology/            <-- The main project folder
│
├── Brewers_Bay_Ecology.Rproj   # The RStudio Project File
└── .Rproj.user/                # User-specific RStudio preferences (hidden)

Why standardizing with .Rproj matters

Opening an .Rproj file launches a fresh R session and automatically sets your working directory (getwd()) to the project root folder.

In traditional workflows, researchers often relied on setwd() with absolute paths (e.g., setwd(“C:/Users/name/Desktop/project”)). Using setwd() with absolute paths guarantees that code will break on anyone else’s computer—or even on your own machine if you move the folder.

RStudio Projects make your workflow portable: as long as all files live inside this directory, the whole folder can be moved, zipped, or shared via GitHub, and all relative file paths will continue to work seamlessly.

2. The Recommended Workspace Layout

A well-structured RStudio project is completely self-contained. Every file required to run your analysis, from raw field CSVs to processing scripts and rendered reports lives within sub directories of the root folder:

Brewers_Bay_Ecology/
│
├── Brewers_Bay_Ecology.Rproj    # RStudio project anchor
│
├── data/                        # Primary data directory
│   ├── raw/                     # Read-only field survey CSVs, raw GPS points
│   └── processed/               # processed data you generated from the raw.
│
├── outputs/                     # Generated deliverables
│   ├── figures/                 # Publication-ready map figures (.png, .pdf)
│   └── tables/                  # Exported summary statistics (.csv)
│
├── scripts/                     # Standalone .R scripts
│   ├── 01_data_cleaning.R
│   ├── 02_my_custom_functions.R
│   └── 03_spatial_analysis.R
│
└── docs/                        # Quarto (.qmd) files and rendered HTML/PDF reports
    └── index.qmd

3. Subdirectory Breakdown & Data Conventions

data/

This folder contains all source and derived data required for your analysis.

  • data/raw/: Stores your original datasets. Convention: Raw data files must be strictly read-only. Never edit, overwrite, or clean raw data files manually in Excel or R[cite: 2].

  • data/processed/: Holds cleaned, transformed, or derived datasets generated programmatically by your R scripts.

outputs/

This folder holds all deliverables generated by your R scripts.

  • Save generated figures (.png, .pdf) and statistical tables here.

  • Convention: Treat everything in outputs/ as disposable and fully reproducible. You should be able to delete the entire outputs/ folder, re-run your scripts, and regenerate every file automatically.

scripts/

This folder houses modular R code files (.R).

  • Separate your processing steps into distinct scripts rather than maintaining one massive, thousands-of-lines-long script.

  • Prefix script names with sequential numbers (e.g., 01_load_and_clean_data.R, 02_site_level_stats.R, 03_plot_site_level_data.R) so anyone opening the project knows the exact order in which to run them.

docs/

This folder is dedicated to Quarto documents (.qmd) and rendered output reports (.html, .pdf).

  • Isolating Quarto files and their rendered assets in docs/ keeps your root folder tidy and makes publishing reports via platforms like GitHub Pages straightforward.
